# HGN launcher-managed runtime proof (not shipping)

The `hgnRuntimePrototypeJar` task packages code selected from the HGN namespace and a Java-agent entrypoint for Minecraft 1.21.4. The launcher's experimental managed path passes this archive with `-javaagent`; it is not a Fabric mod and has no `fabric.mod.json`. Minecraft remains a player-authorized download; neither the repository nor a release may contain a modified or precombined Minecraft or Fabric binary.

The agent is pinned to Fabric Loader 0.19.3. It hooks Fabric's `Knot.init` after Fabric registers mod mixins but before the Mixin bootstrap completes, adds HGN's own archive to Knot's target classpath, and registers `hgn-client.mixins.json`. After Knot initialization it invokes `HgnRuntimeBootstrap.initializeFabric()` in the target classloader. No HGN mod registration is involved. The separate `hgnRuntimeResourcePack` task packages HGN assets for installation/enabling by the launcher; an archive on the Java classpath alone does not make those assets visible to Minecraft's resource manager.

Prototype classes must pass through Loom's production remap before they are copied into the agent archive. Adding named development output after `remapJar` leaves Minecraft-linked method descriptors unresolved at runtime. The filtered agent also excludes Fabric API's nested mod JARs: a managed installation must install compatible `fabric-api-base`, `fabric-networking-api-v1`, and `fabric-resource-loader-v0` as separate Fabric mods and enable the HGN resource pack. The HGN agent itself remains outside Fabric mod registration.

`./gradlew :fabric:proveHgnRuntimePair -Pmc=1.21.4` is the proposed local proof command. It depends on both archives, normalizes ZIP timestamps and order, checks their entries, CRCs, PNGs, fonts, certificate, asset parity against source, and resource `pack_format: 46`, then writes a deterministic JSON proof beside them. The filenames are `hgn-client-runtime-1.21.4-fabric-0.19.3-<clientVersion>.jar`, `hgn-client-resources-1.21.4-fabric-0.19.3-<clientVersion>.zip`, and `hgn-client-runtime-proof-1.21.4-fabric-0.19.3-<clientVersion>.json`. The proof has `schema: 1`, `clientVersion`, `releaseName`, `minecraft`, `loader`, `loaderVersion`, and `agent`/`resourcePack` objects with `file`, exact byte `size`, and lowercase `sha256`. `node tools/runtime-pair.mjs verify fabric/build/libs/<proof-filename>` checks a copied pair against its proof. This is separate from `tools/collect-builds.mjs` and the legacy 35-target mod-JAR manifest.

The JSON alone is only a local consistency record: anyone able to replace it can replace both recorded hashes. Native launcher source now pins the current proof digest to its compiled release identity, fetches all three files from one immutable repository commit, and verifies the downloaded sizes and hashes before staging. The Alpha 1.8.16 proof, agent, and pack are published in `hgn-client-builds`; their streamed SHA-256 values match the Android proof pin and recorded artifact hashes. This verifies publication and integrity, not a packaged game launch or release approval for this candidate.

This remains a non-shipping proof, not an accepted playable client. The development-only fresh-install choice is limited to Minecraft 1.21.4/Fabric Loader 0.19.3. Native source now records pending managed intent with instance creation, stages the verified agent and resource pack outside `mods/`, stages three pinned Fabric API modules, supplies `-javaagent` and `fabric.addMods`, enables the resource pack, and routes managed launches through account/session preparation. Existing installations retain their selected delivery and player mods are not rewritten. The managed path fails closed when its release proof or staged files are unavailable. On October 13, the local production-client smoke in `tools/managed-runtime-smoke.init.gradle` started the agent with only three Fabric API modules, no HGN mod registration, loaded the resource pack, rendered the HGN Menu/Cosmetics/Mods pages, and exited cleanly. This establishes the first-party Knot bootstrap path locally, but not the packaged HGN Launcher path or player acceptance. Paid-account/backend behavior, real server join, Sodium, in-world asset/HUD rendering, and a conflicting-mod title-screen case remain unverified. The standalone `HgnRuntimeAgentPatchTest` checks the exact Knot hook shape without launching the game.
